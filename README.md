# Practica5_TDD

### 1. ¿Qué significa que una prueba esté en estado ROJO?

Que el programa aun no esta capacitado para manejar ese resultado esperado, por lo tanto es un comportamiento nuevo el que se implementa.

<br>

### 2. ¿Qué debe hacerse para llegar a VERDE?

Se empieza a redactar codigo minimo indispensable para que la prueba pase a verde y sea cubierto su comportamiento particular.

<br>

### 3. ¿Qué diferencia existe entre agregar funcionalidad y refactorizar?

Al agregar se crean test nuevos y soluciones nuevas para un problema que nuestro programa no manejaba; mientras que la refactorización es encargada de que un comportamiento que ya se había cubierto por el programa surga con variantes que se le pueden modificar para que siga pasando a verde.

<br>

### 4. ¿Por qué en TDD no conviene implementar todos los requisitos desde el inicio?

Ya que consiste en un proceso de diseño para nuestros programas, si se implementa todo el comportamiento solo se confirmaria lo ya echo, mientras que con TDD se crea un cuestionamiento de lo minimo en incremento de lo posible a mejorar como lo es la refactorización.

<br>

### Reflexión final. 
Este procedimiento de escritura de codigo fomenta que se tenga entendido lo minimo que debe de pasar nuestro programa para usarlo como un escalón para implementar nuevas mecanicas en nuestro código, ademas que se tiene presente que al existir la refactorización tenemos en consideración analizar que parte se puede modificar para que implemente cosas nuevas que queramos agregar, y prevenir la repetición de código sobre todo; tambien el echo de esperar que surga nuestro commit ROJO ayuda a saber lo nuevo que se necesita manejar y no solo el echo de que escribamos codigo y esperar que todo sea verde pasando quiza por alto varios ROJOS.
